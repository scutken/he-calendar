# 系统托盘图标 · 实现说明

> 目标：在 Windows 任务栏托盘区放一个合社日历图标 —— 悬停显示农历/宜忌等可配置内容，左键唤起 uTools 主窗口，右键弹出菜单。
> 与「接管任务栏时钟」方案的区别：**不 hook 输入、不碰 explorer、不拦截通知中心**，只是新增一个自己的托盘图标。

---

## 1. 为什么需要一个 helper 进程

托盘图标只能由「拥有真实 HWND + 消息循环」的进程调用 `Shell_NotifyIcon` 创建。而：

- **uTools 没有任何 Tray API**（官方 `utools.api.d.ts` 里检索不到 `tray` / `NotifyIcon`）
- 插件页面/preload 是 Electron **渲染进程**，没有 FFI，调不到 Win32
- Electron 的 `Tray` API 在 uTools 主进程里，不会暴露给插件

所以插件包里必须带一个独立小程序。另一个选择是写原生 `.node` 模块，但那同样需要 C++ 工具链、还要为 Electron 34 的 ABI 单独编译、且无法复用到将来的独立应用 —— 不划算。

**它能随插件一起装吗？** 能，用户零操作。实测本机已安装的真实插件里就有 `Everything.exe`(1.7MB)、`7za.exe`(574KB)、`7zip`、`capture-x64.exe` 等可执行文件，以及 16 个 `.node` 原生模块，uTools 打包时会把它们放进 `plugins/<hash>.asar.unpacked/` 供运行时执行。所以体验就是「在 uTools 里点安装 → 图标出现」，没有安装向导、没有 UAC、不写注册表、不装服务、不开机自启。

## 2. 技术选型（都是本机实测数据）

| 方案 | 产物体积 | 压缩后(zip) | 常驻内存 | 额外工具链 | 结论 |
|---|---|---|---|---|---|
| **C# / raw Win32（本方案）** | **19.5 KB** | ~9 KB | **24 MB** | 无（系统自带 csc） | ✅ 采用 |
| C# / WinForms | 14.5 KB | 7.6 KB | 29 MB | 无 | 内存更高，弃 |
| Go（纯 syscall） | 1259 KB | **581 KB** | 5.7 MB | 无 | 省 18MB 内存，但插件包 275KB→856KB（3 倍），弃 |
| C++ / Win32 | <100 KB | ~40 KB | ~3 MB | **需装 VS 生成工具** | 本机无工具链 |
| Rust | <1 MB | — | — | **无 linker**（本机 cargo 在但编不出） | 不可用 |
| PowerShell 脚本 | 17 KB | — | **69 MB** | 无 | 太吃内存 + `Bypass` 跑脚本杀软观感差 |

用户拍板：**体积优先**（插件包只涨 ~1.5%）。所以选 C#，但**不用 WinForms**——WinForms 的 29MB 是它的锅，不是 C# 的锅；直接 P/Invoke 后内存降到 24MB、体积也更小。

编译零工具链：Windows 10/11 自带 .NET Framework 4.8，编译器就在
`%WINDIR%\Microsoft.NET\Framework64\v4.0.30319\csc.exe`。

> ⚠️ 这个 csc 是 .NET Framework 自带的老编译器，**只支持 C# 5**：不能用字符串插值、`?.`、`nameof`、表达式体成员、`using static`。

## 3. 架构与数据流

```
uTools 主窗口 preload（Node 环境）
┌─────────────────────────────────────────────┐
│ src/tray/host.js                            │
│  · 用 calendar-core 算今天的农历/宜忌        │
│  · 写配置文件 tray-config.conf（原子替换）    │
│  · spawn helper，读它 stdout 的 JSONL 事件   │
│  · 左键/菜单 → utools.showMainWindow()      │
└───────────────┬─────────────────────────────┘
                │ 配置文件（助手轮询，热更新）
                │ stdout JSONL（事件回传）
                ▼
        public/helper/he-tray.exe（8.5KB 级 C# raw Win32）
        · Shell_NotifyIcon + NOTIFYICON_VERSION_4（128 字符 tooltip）
        · 动态图标：圆角底 + 今天几号（跟随季节/节气配色）
        · 右键菜单：CreatePopupMenu + TrackPopupMenu
        · TaskbarCreated 消息 → explorer 重启后重新注册
        · 看门狗：父进程消失就自我了断并移除图标
```

**为什么数据走文件、事件走管道**：农历/宜忌按天变化、天气按十分钟变化，而 tooltip 里的时间需要每秒刷新。让 helper 自己按模板本地渲染 `%time%`，插件就不必每秒写盘；交互事件是低频且要求低延迟的，走管道最直接。

## 5. 协议

### 插件 → helper：行式配置文件

写在 `utools.getPluginLocalDataPath()/tray-config.conf`（兜底 `%TEMP%/he-calendar/`），**先写 `.tmp` 再 rename**，避免 helper 读到半截内容。

```
enabled=1
maxTooltipChars=127
timeFormat=HH:mm
tooltip=%lunar% · 宜:%yi% · %time%
var.lunar=八月二十
var.yi=祭祀 解除 结网 畋猎
icon.mode=date
icon.bg=#8C4A3C
icon.fg=#FFFFFF
menu=open|打开合社日历
menu=settings|托盘设置
menu=-|-
menu=quit|关闭托盘图标
```

### helper → 插件：stdout JSONL

```json
{"type":"start","pid":1234,"parentPid":5678}
{"type":"nim-add","ok":true,"tipLen":74}
{"type":"icon","mode":"date","label":"30","size":16}
{"type":"tooltip","text":"…","length":74}
{"type":"ready"}
{"type":"click","button":"left"}
{"type":"menu","item":"settings"}
{"type":"taskbar-recreated"}
{"type":"error","message":"…"}
{"type":"exit"}
```

## 6. 悬停字段与模板

可用变量（设置页里也会列出来）：

`%lunar%` `%ganzhi%` `%term%` `%nextTerm%` `%festival%` `%zodiac%` `%yi%` `%ji%` `%chong%` `%wuxing%` `%pengzu%` `%taishen%`
以及由 helper 本地渲染的 `%time%` `%timeSec%` `%date%` `%weekday%` `%day%`

规则（这几条是踩坑踩出来的）：

- `%yi%` / `%ji%` **只输出词条本身**（`祭祀 解除 结网 畋猎`），前缀要写在模板里（`宜:%yi%`）——
  早期版本把「宜:」写在字段值里，结果用户写 `宜:%yi%` 会得到「宜:宜:…」
- `%yi(3)%` 这种写法会被**归一化成 `%yi%`**（历史上 helper 只认 `%key%`，不归一就会把字面量印到托盘上）
- 未收录的变量会被**自动删除**，设置页会给出警告（避免留下「满:」这种悬空前缀）
- 原生 tooltip 上限：helper 用 `NOTIFYICON_VERSION_4 + NIF_SHOWTIP`，`szTip` 可用 **128 字符**（已实测 74 字符成功写入）；失败时自动回退到 63

## 8. 已知限制

1. **uTools 重启后要先进入一次插件**才会拉起 helper（preload 只在插件 webview 创建时执行）。要彻底解决得靠 uTools 的自启能力或后台常驻设置，待确认。
2. **Windows 11 默认把新托盘图标收进「显示隐藏的图标」溢出区**，用户需要手动拖到任务栏上。首次开启时应用内已有提示文案。
3. helper 的生命周期跟随宿主：uTools 退出 → 父进程看门狗触发 → helper 自己移除图标后退出，不会留孤儿进程或幽灵图标。
4. 图标由 GDI+ 动态绘制（约多占 7MB 内存），换来「托盘直接显示今天几号」。
5. `.exe` 是否会被 uTools 打包时自动解包到 `.asar.unpacked` —— 别的插件证明可行，但**我们自己的包还没真机打过**，需要发布前验证一次；host.js 里已同时探测 asar 与 asar.unpacked 两种路径。

## 10. 踩坑记录

1. **csc 只支持 C# 5**：`/langversion` 提不上去（这是 .NET Framework 自带的老编译器）。写了 `?.` 或 `$"..."` 会直接编不过。
2. **`/target:winexe` 的 stdout 需要父进程给管道**：`bp run` 抓不到它的输出（看起来"没有输出"），但用 Node `spawn` + `stdio:['ignore','pipe','pipe']` 就能实时收到 —— 之前误判过一次，以为协议不通。
3. **csc 的输出目录必须已存在**：否则报 `error CS1567: 生成 Win32 资源时出错`，看起来像语法问题，其实是目录不存在。
4. **不要指望 PowerShell 侧接收 C# 结构体返回值**（上一轮教训）：会被解包成数组。几何计算放在 C# 里算完再回传。
5. **`TaskbarCreated` 必须处理**：explorer 崩溃/重启后托盘图标会消失，需要重新 `NIM_ADD`。
6. **`TrackPopupMenu` 前要 `SetForegroundWindow`，之后要补 `PostMessage(WM_NULL)`**，否则菜单可能不关闭。
7. **单实例互斥**：插件多窗口重复拉起会产生两个图标，用命名 Mutex 兜底，并按 `utools.getWindowType() === 'main'` 只启动一次。
